1. EXECUTIVE ARCHITECTURAL SUMMARY
--------------------------------------------------------------------------------
The database architecture for PRAQEN has transitioned from a single-currency (BTC)
prototype to an institutional-grade, multi-asset (BTC + USDT TRC-20) P2P financial 
exchange.

Key Architectural Principles:
1. Authoritative Ledger Model:
   - The 'wallets' table is the single authoritative source of truth for user 
     balances (balance_btc, locked_balance_btc, balance_usdt, locked_balance_usdt).
   - 'user_wallets' tracks on-chain addresses and monitor checkpoints.
   - Legacy mirror columns ('user_balances') are kept synchronized via PostgreSQL 
     triggers and atomic functions.

2. Atomic Database-Level Operations (ACID Compliance):
   - All financial balance modifications (deposits, internal transfers, escrow 
     locks, releases, refunds, withdrawals) execute inside PostgreSQL PL/pgSQL 
     SECURITY DEFINER functions with row-level locks and strict idempotency keys.

3. Security & Row Level Security (RLS):
   - Public/Anon keys have zero access to private user data or balance modifications.
   - Backend operates securely via the Supabase Service Role Key.

4. AI Support & Vector Infrastructure:
   - pgvector extension (vector(1024)) enabled for semantic search in customer support.

5. 3-of-4 Moderator Quorum System:
   - Multi-party dispute voting, threaded comments, and immutable oath logs.

6. Company Books & Administration:
   - Full ERP tables for loans, expenses, staff directory, security events, and audit logs.

1. wallets
   - Purpose: Authoritative single source of truth for user balances.
   - Primary Key: id (UUID)
   - Foreign Keys: user_id REFERENCES users(id) ON DELETE CASCADE
   - Columns: id, user_id, address, private_key, balance_btc, locked_balance_btc,

5. STORED PROCEDURES / PL/PGSQL RPC FUNCTIONS
================================================================================

1. public.praqen_credit_deposit(p_user_id, p_currency, p_amount, p_onchain_balance, p_idempotency_key, p_note)
   - Atomically records ledger row, increments balance, syncs mirrors, and updates checkpoints.

2. public.praqen_internal_transfer(p_sender_id, p_recipient_id, p_currency, p_amount, p_idempotency_key, p_note)
   - Locks both wallet rows in sorted user_id order to eliminate deadlocks, debits sender, 
     credits recipient, and writes dual ledger entries atomically.

3. public.praqen_release_escrow(p_trade_id, p_receiver_id, p_company_id, p_amount_btc, p_fee_btc, p_amount_usd, p_tx_hash)
   - Atomically releases escrowed cryptocurrency to buyer and fee to platform treasury.

4. public.praqen_refund_escrow(p_trade_id, p_provider_id, p_amount_btc, p_reason)
   - Atomically refunds locked escrow balance back to the seller.

5. public.praqen_reject_withdrawal(p_tx_id, p_ceo_id, p_reason)
   - Atomically transitions a pending withdrawal to PROCESSING, refunds user balance, 
     and marks status as REJECTED with CEO reason.

6. DATABASE TRIGGERS

1. trg_wallets_mirror_sync
   - Attached to: public.wallets (AFTER UPDATE OF balance_btc, balance_usdt)
   - Action: Copies updated balances directly into 'user_balances' and 'user_wallets' 
     to prevent mirror drift.

2. trg_credit_referral_earnings
   - Attached to: public.affiliate_earnings (AFTER INSERT)
   - Action: Increments referrer's 'referral_earnings_btc' whenever an affiliate row 
     with status 'CREDITED' is created.

3. kb_articles_updated_at
   - Attached to: public.kb_articles (BEFORE UPDATE)
   - Action: Auto-updates updated_at timestamp.
